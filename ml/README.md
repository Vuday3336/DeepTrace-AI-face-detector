# DeepTrace — ML pipeline

Everything from data audit to ONNX export is implemented and tested end-to-end on synthetic data.
**No results yet** — every number comes from running the Kaggle notebooks below on the real data.

```
ml/
├── configs/        preprocess.yaml (the preprocessing contract), data.yaml, diffusion_prompts.yaml
├── requirements/   pinned deps, split by where they run (see below)
├── scripts/        every pipeline step as a CLI (notebooks just call these)
├── notebooks/      Kaggle notebooks, generated by notebooks/build_notebooks.py
├── configs/train/  one YAML per model; configs/eval.yaml (calibration, robustness grid, selection rule)
├── src/deeptrace_ml/
│   ├── data/           manifests, dataset discovery, splits, dedupe, image metadata
│   ├── preprocessing/  safe decode, MTCNN, square crop, JPEG — shared with the backend
│   ├── audit/          shortcut features, spectra, trivial classifier, plots
│   ├── models/         model registry + BinaryClassifier wrapper (timm)
│   ├── training/       datasets/augmentations, fine-tuning engine, CLIP linear probe
│   ├── evaluation/     metrics + bootstrap CIs, calibration/threshold, test sets, perturbations, plots
│   ├── explain/        closed-form Grad-CAM + attention rollout (numpy), pytorch-grad-cam wrappers
│   ├── export/         ONNX export with heatmap outputs, model card
│   ├── serving/        bundle loader + analyzer — the exact code path the API runs
│   └── utils/          hashing, seeds, env capture, JSON, logging, output paths
├── data/manifests/ committed manifests (raw/processed images are git-ignored)
├── reports/        JSON outputs — the ONLY source of numbers for docs/README
└── tests/          68 tests (synthetic data; includes Grad-CAM-vs-autograd parity and ONNX export)
```

## Where each step runs (all free)

| Step | Where | Why |
|---|---|---|
| Unit tests, own-photo set, small experiments | Your laptop (CPU) | Fast, no quota |
| Diffusion face generation | Kaggle GPU — `notebooks/00_generate_diffusion_faces.ipynb` | Needs a 16 GB GPU |
| 140k manifest, audit, dedupe, preprocessing | Kaggle GPU — `notebooks/01_data_prep_and_audit.ipynb` | 140k dataset is already on Kaggle; MTCNN on GPU |
| Training, calibration, evaluation (per model) | Kaggle GPU — `notebooks/02_train_and_evaluate.ipynb` | Fine-tuning needs a GPU |
| Robustness, explainability, FFT, ONNX export, latency, model selection | Kaggle GPU — `notebooks/03_robustness_explain_export.ipynb` | Many forward passes |

## 1. Local setup (Windows, PowerShell)

Tested locally with Python 3.13; Kaggle currently runs Python 3.11/3.12. The code targets 3.11+.

```powershell
cd deeptrace\ml
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements\dev.txt
.venv\Scripts\python.exe -m pip install -r requirements\torch-cpu.txt --index-url https://download.pytorch.org/whl/cpu
.venv\Scripts\python.exe -m pip install -r requirements\facenet.txt --no-deps
.venv\Scripts\python.exe -m pip install -r requirements\train.txt
.venv\Scripts\python.exe -m pip install -e . --no-deps
.venv\Scripts\python.exe -m pytest
```

Why `--no-deps` for facenet-pytorch: its metadata pins torch 2.2.x, which would downgrade PyTorch
(and on Kaggle, break the CUDA build). Its MTCNN code works on current torch — verified with
torch 2.9.1 in this repo.

## 2. Put the repo on GitHub (Kaggle clones it)

```powershell
cd deeptrace
git init
git add .
git commit -m "Phase 1-2: architecture, data pipeline, shortcut audit"
git branch -M main
git remote add origin https://github.com/<YOUR_GITHUB_USERNAME>/deeptrace.git
git push -u origin main
```

A public repo is simplest (Kaggle clones without credentials). Then set `REPO_URL` in the first cell
of each notebook.

## 3. Cross-generator fakes (Kaggle, GPU)

1. Kaggle → **Create → Import Notebook** → upload `notebooks/00_generate_diffusion_faces.ipynb`.
2. Settings: **Accelerator: GPU T4 x2** (or P100), **Internet: On**.
3. Set `MODELS = ["sdxl"]` → **Save Version → Save & Run All**. Repeat with `["flux-schnell"]`
   (a separate run, since the 12 h limit may not fit both).
4. From each finished version: **Output → New Dataset** (e.g. `deeptrace-generated`).

Meanwhile, apply for **DiFF** access (free, research use). If approved, add it as an extra fake
source in step 4.

## 4. Data prep + shortcut audit (Kaggle, GPU)

1. Import `notebooks/01_data_prep_and_audit.ipynb`; GPU + Internet on.
2. **Add Input** → "140k Real and Fake Faces". Optional: your generated dataset + a CelebA-HQ dataset
   (then fill `CELEBAHQ_DIR` / `GENERATED_DIR` in section 1b).
3. **Save Version → Save & Run All**.
4. When it finishes: **Output → New Dataset** named `deeptrace-processed` (Phase 3 trains on it), and
   download `deeptrace_phase2_artifacts.zip` → copy its `ml/data/manifests`, `ml/reports`,
   `docs/plots` into your repo and commit.

The same steps as plain commands (Kaggle terminal or any Linux box):

```bash
python scripts/build_manifest_140k.py --search-root /kaggle/input --workers 4
python scripts/run_audit.py --dataset 140k --manifest data/manifests/140k_raw.csv.gz --root 140k=<ROOT printed above>
python scripts/dedupe.py --manifest data/manifests/140k_raw.csv.gz --root 140k=<ROOT> --workers 4
python scripts/prepare_dataset.py --manifest data/manifests/140k_raw.csv.gz --root 140k=<ROOT> \
    --duplicates data/manifests/duplicates_drop.csv --out-root /kaggle/working/processed --device auto --batch-size 128
python scripts/run_audit.py --dataset 140k --manifest data/manifests/140k_raw.csv.gz --root 140k=<ROOT> \
    --processed-manifest data/manifests/140k_processed.csv.gz --processed-root /kaggle/working/processed
```

## 5. Your own sanity-check set (local, CPU)

Collect ~100 phone photos of consenting people and ~100 AI faces you generate, in two folders. Then:

```powershell
.venv\Scripts\python.exe scripts\organize_external.py --dataset own --out-root data\raw\own `
    --source "phone:real:D:/Pictures/deeptrace_phone" --source "mygen:fake:D:/Pictures/deeptrace_ai"
.venv\Scripts\python.exe scripts\prepare_dataset.py --manifest data\manifests\own_raw.csv.gz `
    --root own=data\raw\own --out-root data\processed --device cpu --batch-size 8
.venv\Scripts\python.exe scripts\run_audit.py --dataset own --manifest data\manifests\own_raw.csv.gz `
    --root own=data\raw\own --processed-manifest data\manifests\own_processed.csv.gz `
    --processed-root data\processed --sample-per-group 100 --spectrum-per-group 100
```

Phone photos contain EXIF (often GPS). `data/raw/` is git-ignored — keep it that way. Processed crops
have all metadata stripped.

## 6. Train, evaluate, explain, export (Kaggle, GPU)

1. `02_train_and_evaluate.ipynb` — attach `deeptrace-processed`, set `MODEL`, **Save & Run All**. Do it
   for `effnet_b0`, `convnext_tiny` and `clip_probe` (optionally `vit_small`). Save each output as a
   dataset `deeptrace-runs-<model>`. Rerun the best model(s) with `SEEDS = [42, 43, 44]`.
2. `03_robustness_explain_export.ipynb` — attach `deeptrace-processed`, the 140k dataset and all
   `deeptrace-runs-*`; **Save & Run All**. It picks the deployment model with the pre-registered rule.
3. Copy `ml/reports`, `docs/plots`, `docs/METRICS.md` from the artifacts zip into the repo, write
   `docs/EXPLAINABILITY.md`, and upload the winning bundle:
   `python scripts/upload_model_to_hub.py --bundle-dir artifacts/<winner> --repo-id <user>/deeptrace-model`.

The same pipeline as plain commands:

```bash
python scripts/train.py --config configs/train/effnet_b0.yaml --manifest data/manifests/140k_processed.csv.gz \
    --data-root <processed> --run-dir runs/effnet_b0_seed42
python scripts/train_clip_probe.py --manifest data/manifests/140k_processed.csv.gz --data-root <processed>
python scripts/predict.py --checkpoint runs/effnet_b0_seed42/best.pt --manifest data/manifests/140k_processed.csv.gz \
    --manifest data/manifests/crossgen_processed.csv.gz --data-root <processed> --out reports/predictions_effnet_b0.csv
python scripts/calibrate.py --predictions reports/predictions_effnet_b0.csv --model-name effnet_b0
python scripts/evaluate.py --predictions reports/predictions_effnet_b0.csv \
    --calibration reports/calibration_effnet_b0.json --model-name effnet_b0
python scripts/robustness.py --checkpoint runs/effnet_b0_seed42/best.pt --model-name effnet_b0 \
    --processed-manifest data/manifests/140k_processed.csv.gz --root 140k=<raw 140k> \
    --calibration reports/calibration_effnet_b0.json
python scripts/explain.py --checkpoint runs/effnet_b0_seed42/best.pt --model-name effnet_b0 \
    --predictions reports/predictions_effnet_b0.csv --calibration reports/calibration_effnet_b0.json --data-root <processed>
python scripts/fft_analysis.py --processed-manifest data/manifests/140k_processed.csv.gz --data-root <processed>
python scripts/export_model.py --checkpoint runs/effnet_b0_seed42/best.pt --calibration reports/calibration_effnet_b0.json \
    --eval-report reports/eval_effnet_b0.json --robustness-report reports/robustness_effnet_b0.json \
    --version 1.0.0 --out-dir artifacts/effnet_b0
python scripts/benchmark_latency.py --bundle-dir artifacts/effnet_b0 --threads 2
python scripts/compare_models.py --eval reports/eval_effnet_b0.json --latency reports/latency_effnet_b0.json
python scripts/render_metrics_md.py
```

Set `DEEPTRACE_ARTIFACTS_DIR=<scratch dir>` to send reports/plots elsewhere (used for smoke tests, so
synthetic numbers never land in `ml/reports` or `docs/plots`).

## Reading the audit

| Result | Meaning | Action |
|---|---|---|
| Raw metadata AUC ≫ 0.5 | File properties leak the label | Expected on raw data — that's why preprocessing exists |
| Processed metadata AUC (no file size) ≈ 0.5 | Encoding shortcuts removed | ✅ |
| Processed metadata AUC still ≫ 0.5 | A shortcut survived | Check `top_features` in `reports/audit_*.json` before training |
| Processed pixel-stats AUC > 0.5 | Low-level colour/texture differences remain | Partly legitimate signal; report it, and watch for it in Grad-CAM |
| Very different `crop_clamped` or `no_face` rates between classes | The crop step treats classes differently | Investigate before training |
